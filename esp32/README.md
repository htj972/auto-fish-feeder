# 自动喂鱼器 · ESP32-C3-FH4

基于 PlatformIO + Arduino 的初版固件。目标 ESP32-C3FH4，160 MHz、封装内 4 MB Flash；使用 `esp32-c3-devkitm-1` 编译定义作为基础，不代表 PCB 引脚与开发板一致。

## 已实现

- N20 电机驱动使能输出，单次运行 100～30000 ms，独立 esp_timer 定时关闭，禁止并发投喂。
- 每日 8 组任务，各自配置时间、时长和启用状态；默认全部关闭。
- Web 中文管理页：状态、任务设置、手动投喂、停止、WiFi 配网。
- NVS 保存任务、WiFi 信息及各任务当日执行标记；同一任务每天最多触发一次，重启不重复补喂。标记先保存再启动，突然断电可能少喂，不会恢复未完成的投喂。
- NTP 校时，北京时间。未校时暂停自动任务，手动投喂仍可用；同步后短期断网使用系统时钟继续运行。断电不能保持时间。
- 实体按键按住 2 秒开始投喂，松手停止；提前松手取消并清空进度。持续按住最多运行 30 秒，超时后必须松手再按。上电时已按住的按键保持 3 秒进入配网，该轮操作不触发投喂。
- 待机双击按键显示IP 5秒，双击两次释放间隔不超过350ms，每次按下须稳定至少40ms、时长不超过350ms；单击无动作，第二次改为长按则取消双击判断。
- 按键由独立5ms周期任务采样和控制电机，主循环只处理配网请求与报警；避免Web、OLED、WiFi处理拖慢长按计时。2秒以首次检测到并通过40ms消抖的按下起点计算，仍需在真机上验证调度和电机启动延迟。
- SSD1306 128×32 I2C OLED 按确认的预览显示纯英文点阵界面：左上45° WiFi 图标、中上当前时间、右上电池填充和百分比，主体大字投喂时间与同行小字时长。
- 无已保存 WiFi 或连接失败约 20 秒后打开配网热点，支持 DNS 引导。

## 模块结构

代码使用 4 个空格缩进、100 列换行和完整控制语句花括号；`.clang-format` 保存 C/C++ 格式规则，`.editorconfig` 统一 UTF-8、LF 换行和文件末尾换行。使用支持 clang-format 的编辑器即可按同一规则格式化。

每个模块的公开接口放在 `include/同名.h`，实现放在 `src/同名.cpp`。

| 模块 | 职责 |
|---|---|
| main | 初始化顺序与主循环调度 |
| cpu_power | 固定80MHz运行与启动频率检查 |
| motor | 电机输出、投喂互斥、定时停止 |
| oled_display | OLED 初始化与状态绘制 |
| web_ui | Web 页面、路由和表单校验 |
| network | WiFi 连接、异步扫描、热点配网、DNS、mDNS 与重连 |
| button | 独立采样任务、2秒防误触确认、松手停机、双击IP、上电按住配网 |
| power_monitor | TP4056 状态、电池 ADC 与超量程检测 |
| scheduler | 时间同步、每日任务和下次投喂时间 |
| settings_store | NVS 参数、WiFi 凭据和当日任务标记 |
| app_state | 公共报警信息与引脚冲突检查 |

引脚、电平和分压参数统一保留在 `include/board_config.h`。NVS 读写经由存储模块接口完成，Web 不直接操作 NVS；电机定时器、显示驱动、网络服务对象和采样状态由各自模块管理。重构保留原有设置格式与 NVS 键，已有配置无需迁移。

`scripts/relative_map.py` 将链接器 map 文件参数转换为工程内相对路径，避免 Windows RISC-V 工具链在中文目录中无法创建 map 文件。

## 必须配置的接线

接线已写入 `include/board_config.h`。电机 GPIO10 高电平有效，按键 GPIO5 低电平有效，OLED SCL=GPIO3、SDA=GPIO4。

| 配置 | 含义 |
|---|---|
| MOTOR_PIN | 电机驱动器的使能/单向控制脚 |
| MOTOR_ACTIVE_HIGH | 驱动器有效电平，默认高电平 |
| BUTTON_PIN | 按键接 GPIO 与 GND，使用内部上拉 |
| OLED_SDA / OLED_SCL | OLED I2C 引脚 |
| OLED_ADDRESS | 默认 0x3C，屏幕确认为 SSD1306 128×32 后使用 |

TP4056 CHRG 接 GPIO20，STDBY 接 GPIO21，以内部上拉读取，低电平有效。两者均高阻只表示未指示充电/完成，不能区分无输入电源、温度暂停或其他状态；两者同时低提示检查充电器，不能仅据此断定故障。模块 LED 若通过限流电阻连接 5V，其支路仍可能向状态节点注入电压，必须核实高阻时 GPIO 电压不超过 3.3V，必要时隔离 LED 支路并使用独立 3.3V 上拉。

电池采样已改为 GPIO1（ADC1_CH1），接线：**电池正极→100kΩ→GPIO1→100kΩ→GND**。满电 4.2V 时 ADC 输入约 2.1V，`BATTERY_ADC_ENABLED=true`，使用 11dB 衰减、16 次平均和 2 倍换算。超过 2.4V 或原始值接近饱和时仅显示超量程，不显示错误电压。建议 ADC 点到 GND 加 100nF 滤波，降低 50kΩ 等效源阻抗对采样的影响，并用万用表校准 `BATTERY_CALIBRATION`。核心板GPIO2自带到3.3V的上拉，会改变分压比例，因此分压中点需从GPIO2移接GPIO1；GPIO2原上拉可保留，GPIO1应无额外上拉及其他连接。之前讨论的 10kΩ/100kΩ 或 33kΩ/100kΩ 接法均不适用于当前固件，烧录前务必完成电阻更改。

电机/按键/OLED 引脚验证允许 GPIO 0、1、3～7、10。GPIO20/21 已专用于状态输入，固件日志改用原生 USB CDC（GPIO18=D−、GPIO19=D+），不启动 UART0。不要把外部 USB-UART 的 TX 接入 GPIO20 与充电状态脚争用；ROM 下载和启动阶段 UART 行为不受应用 CDC 设置控制，优先使用原生 USB，若需 UART 下载应隔离充电状态线路。

N20 不能直接接 ESP32 GPIO，应通过匹配电压、电流的 MOSFET 或电机驱动器供电，共地并配置续流及去耦。驱动使能应有硬件默认关断电阻，确保上电、复位和启动前不转动。目前控制接口假设单向使能；双输入 H 桥需按驱动型号扩展。

## 编译、烧录、使用

在 VS Code 使用 PlatformIO 打开本目录，或运行：

```powershell
pio run
pio run -t upload --upload-port COM实际端口
pio device monitor -b 115200 --port COM实际端口
```

首次编译会下载 RISC-V 编译器和 Adafruit 库。已开启原生 USB CDC，需 PCB 将 GPIO18/19 接到 USB 数据线；只有充电功能的 USB 接口无法提供日志或下载。应用不等待 USB 连接，脱离电脑仍可运行。

1. 上电打开 115200 波特率串口，读取 `FishFeeder-…` 热点及密码。
2. 手机连接该热点，打开 `http://192.168.4.1/`。页面自动异步扫描附近2.4GHz WiFi，也可点击“重新扫描”；列表按RSSI降序排列，相同SSID保留最强信号，最多24项，显示加密/开放状态。选择SSID后输入密码；隐藏网络仍可手动输入。扫描15秒超时提示失败，设备正在连接或投喂时可能暂时拒绝新扫描，可稍后重试。
3. 连接成功后串口打印局域网管理地址，OLED 自动显示IP 8秒，再返回主页面；待机时双击按键可再次显示IP 5秒，未联网显示 `OFFLINE`。同一局域网中也可尝试 `http://fishfeeder.local/`（依赖客户端和网络支持mDNS）。连接路由器成功并取得IP后保留5秒供网页读取结果，再关闭配网热点及DNS，仅保留STA连接；手机需切回同一局域网，通过设备局域网IP访问网页。无网络配置或连接失败时仍会打开配网热点；需要手动配网时，上电前按住按键并保持 3 秒。
4. 校时完成后设置任务并保存。Web中的手动时长和每项任务时长统一以**秒（s）**输入，范围0.1～30，最多三位小数（例如 `0.5`、`2`、`1.234`）。内部和NVS仍使用毫秒，原有设置不迁移、不改变时长；更新固件后请刷新旧页面再提交。按键持续投喂与Web固定时长投喂分别处理。先空载测试，实际时长与饲料重量需实物标定。
5. Web“屏幕亮度”提供1～100%的OLED亮度滑块：拖动预览，点击“保存亮度”后写入NVS，重启恢复。预览不会频繁写Flash，也不会触发重复帧刷新；亮度通过SSD1306全屏对比度调节，视觉亮度不保证线性。首次默认56%，对应0x8F对比度，承接原先128×32屏幕亮度；100%对应255，可比旧默认更亮。亮度单独使用 `oled_level` 键，不改变已有任务参数布局。

热点密码由芯片标识生成，适合原型调试，量产应改为随机且可贴标的独立密码。管理页当前供可信家庭局域网使用，无登录、HTTPS 或远程访问功能；提交操作带启动时随机表单令牌。WiFi 凭据保存在 NVS，页面不回显密码。

## 调度与异常边界

- 任务在目标分钟内触发；错过整个分钟不补喂。同一时刻启用多项，顺序执行首项，其余在电机忙时跳过并显示报警。避免配置重叠时段。
- 保存任务不会清除当日执行标记；当日已触发的同一行，即使修改时间也不会再次自动投喂。
- 报警为本次启动期间的软件错误信息，在 Web 显示详情，OLED 提示查看 Web；未配置 OLED 时继续无屏运行。
- 本版没有电流、转速或料位传感器，因此不能检测真实堵转或缺料。电量百分比使用单节锂电电压曲线估算，不是库仑计结果；进入充电时锁定估计百分比，图标内显示静态闪电，充电完成信号有效时更新为100%。尚未加入低压停机策略。30秒限时是软件保护，不替代硬件过流保护。
- OLED 仍假设 SSD1306 128×32、0x3C，电机驱动已按单向高有效使能实现。Web 配网已实现，AirKiss 未实现。

## 上板验收

1. 上电、复位及空闲时确认 GPIO10 为低、电机不转；先检查电池分压安全及充电状态节点的电压。
2. 先断开电机供电测量控制输出：不足2秒松手不启动，满2秒开始，松手停止；持续按住达到30秒停机且不会自行重启。Web投喂仍使用单独保存的手动时长。
3. 设置一分钟后的任务，验证时长与 OLED；同一分钟重启，确认不会重复投喂。
4. 测试错误密码、断路由器、重新连接、上电按住3秒配网与保存后重启；确认上电配网的这一轮按住及释放均不启动电机。
5. 无网络冷启动确认自动任务暂停；恢复网络后确认北京时间与下一任务正确。
6. 拔除 OLED 验证报警和 Web 功能，测试投喂期间访问网页或切断网络是否按时停机。
7. 手机保持管理页打开并扫描/刷新页面，同时测量从按下到GPIO10变高是否约2秒；确认松手停机，单击无动作，双击显示IP 5秒且电机不转，长按不误触IP页。
8. 验证0.1秒、0.5秒、2秒、30秒保存和重启后时长不变；测试WiFi重复SSID、特殊字符、扫描失败、重新扫描、手动隐藏SSID，并核对手机实际可访问的IP。
9. USB日志确认固定80MHz，访问Web、扫描WiFi和投喂时均不升频。检查NTP时间、定时投喂、按键2秒与松手停机，再测量芯片温度和整板电流。
10. 检查充电静态闪电与百分比，使用I²C逻辑分析仪确认画面不变时无重复显示帧传输，分钟、电量或状态变化时更新；测试亮度最低/最高、预览未保存后重启、保存后重启及网络请求失败。

本工程未经过实物验收，不应直接用于无人值守投喂。

## OLED 页面与电池显示

断网后重新配网：提交WiFi配置会保留AP，仅关闭STA，等待200ms后使用新凭据重新连接。关闭底层自动重连，由网络模块统一在连接超时后重试；每次重试重新加载已保存凭据，避免旧连接配置干扰。连接超时保留配网热点，连接目标网络成功后关闭热点。串口输出连接请求状态和超时状态，不输出家庭WiFi密码。`tests/host/network_test.cpp`验证该流程；桌面模拟无法替代真实路由器、无线事件和手机连接的验证。

- 主页面：顶部左侧45°扇形WiFi图标按RSSI显示三档强度，离线为 `--`；顶部时间左移至x=42。右侧非充电时显示电池填充和百分比，充电时改为图标内静态闪电，百分比位置不变，不额外显示 `+`。
- 主体：例如左侧大字 `20:30`，右侧上方小字 `3 TASKS`、下方小字 `+5s`，两行右对齐。数量表示已启用的每日任务总数，不是今日剩余数；单项显示 `1 TASK`。无启用任务显示 `0 TASKS` 和 `--:--`，隐藏时长；未校时仍显示启用数量，但时间为 `--:--`、隐藏时长。
- 按键确认：`HOLD 2s` 与实时进度条，松手恢复主页；手动投喂显示 `FEEDING` / `RELEASE TO STOP`。进度每50ms评估，配网滚动每500ms评估，其余画面每250ms检查内容变化；内容不变不绘制，最终像素一致也不进行I²C帧传输。定时或Web投喂显示 `FEEDING` / `AUTO / WEB`。
- 配网：仅显示 `SSID:`、`PASS:`、`WEB:` 三行，使用真实热点名称、热点密码和IP。每行较长的内容往返滚动，标签固定，不省略凭据。正常联网后切回主页。
- IP提示：联网成功显示8秒，双击显示5秒；长按进度和运行中的投喂提示优先于IP页面。
- 电池信息尚未采到、ADC超量程或电压低于有效估算区间时显示空电池和 `--`。无电池通过BAT电压近似判断，无法保证识别充电器维持BAT端电容电压的无电池状态；如需可靠检测，应增加独立电池在位检测。建议测试电池拔除、充电中拔除、低电量及电机负载下的电压波动。
- 异常时主页面显示 `ALERT` / `SEE WEB`，Web保留完整错误信息。

按键桌面测试位于 `tests/host/button_test.cpp`，使用GPIO、时钟和电机桩执行实际按键模块代码，覆盖1999ms取消、重新累计2秒、释放停止、30秒结束后不重启、不同投喂来源不互相误停及上电配网互斥。它不替代实物电气和停机延迟测试。

电源桌面测试位于 `tests/host/power_test.cpp`，覆盖未采样、2倍电压换算下的电量估计、充电百分比锁定、充满100%、无有效电池电压和ADC饱和时显示未知。新增 `duration_test.cpp` 验证秒/毫秒精确换算、边界与非法输入；按键测试新增双击间隔、长按取消双击及millis溢出。三组测试均通过。`node tests/web_scan_test.cjs` 执行真实网页脚本，验证自动扫描、轮询、SSID选择、手动输入保留及请求失败提示；不访问真实WiFi。

`cpu_power_test.cpp` 运行实际频率模块，验证固定80MHz与重复初始化不重复切换。`display_test.cpp` 配合 `tests/display_stubs` 运行实际OLED模块，验证静态待机/充电不重复传输、闪电像素、分钟/电量/任务变化、进度条更新、配网滚动及IP超时，并验证亮度1%/100%边界、无效值和调光不刷新帧。`settings_test.cpp` 模拟NVS，执行真实参数模块验证亮度保存/重启恢复及原投喂参数保留。网页脚本测试覆盖亮度预览、串行提交、保存与失败提示。显示桩中的字符仅用于判断像素变化，不代替真实字体与屏幕的视觉验收。相关桌面测试均通过。

## CPU固定80MHz

`platformio.ini` 将 `board_build.f_cpu` 固定为 `80000000L`，程序启动时再次确认80MHz。Web升频逻辑已移除，访问页面、配网扫描、投喂、按键、NTP和充电均保持80MHz。USB输出实际启动频率，设置失败时通过Web报警。

OLED亮度由用户通过Web设置；无交互达到配置时间后发送SSD1306硬件关屏命令（默认30秒，可在Web中设置15～90秒，或选择常亮）并停止帧传输，按键按下或释放、Web手动投喂及亮度调节可唤醒并重新计时。持续按住期间保持亮屏，松手后重新计时；唤醒先更新画面再开屏，保留设置的亮度。普通Web访问、联网、充电和自动投喂均不唤醒；Web手动投喂和亮度预览/保存会唤醒。开机亮屏30秒，配网页面也遵循此规则。`OLED_IDLE_MS`可调整超时。

关屏使用控制器的Display OFF模式，并非物理切断OLED供电；不进入ESP深睡眠，WiFi继续在线、系统时间和定时任务继续运行。实际发热和功耗改善需要测量，不能由编译或桌面测试推断温降幅度。

## 编译验证

2026-10-20 添加Web OLED亮度预览/保存并固定CPU为80MHz后，使用 `pio run` 构建通过，生成 `.pio/build/esp32c3_fh4/firmware.bin`。RAM使用43660字节（13.3%），应用Flash使用881334字节（默认应用分区的67.2%）。完整编译时Arduino 2.0.14框架自身的 `esp32-hal-uart.c` 存在一条非void函数空return警告；项目代码编译通过。新版本尚未进行硬件烧录或实物功能验证。
